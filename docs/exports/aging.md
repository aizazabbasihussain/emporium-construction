# Export: Aging (`aging`)

Schema version: 1

Open receivables (by client) and open payables (by vendor) in the aging buckets as of the end date. The first four buckets have a column each; any later bucket is added to bucket_4.

## Source

Receivables aging per customer and payables aging, as of the end date. The `side` filter shows one side.

## Columns

| Column | Type | Meaning |
| --- | --- | --- |
| side | text | `receivable` or `payable`. |
| party | text | Client, vendor or subcontractor name. |
| bucket_1 | money | First aging bucket, PKR. |
| bucket_2 | money | Second aging bucket, PKR. |
| bucket_3 | money | Third aging bucket, PKR. |
| bucket_4 | money | Fourth and later aging buckets, PKR. |
| total | money | Total outstanding, PKR. |
| account_code | text | Chart of accounts code of the line. Blank if the line is untagged or is not a document line. |

Types: `text`, `date` (yyyy-mm-dd), `money` (PKR, two decimals), `qty` (four decimals), `int`.

## Order

Receivable rows, then payable rows, in the order the owning module gives.

## Header block and footer

Above the data: report name, filters, period, fiscal year, schema version, generated at (Asia/Karachi), generated by, and the number of untagged lines. Below the data: the row count and a totals row with the sum of every money column.

## Control totals

total is tied to the total of each aging report. A difference aborts the run with an error and nothing is stored.

## Files

An Excel file and a CSV file (UTF-8 with a byte order mark). The checksum in the run log covers the data section only (column keys and rows), so the same data gives the same checksum on any day.

## Changes

A change of columns is a new schema version of this file; earlier versions stay reproducible for runs already made.
