# P1-19 Operational reports

## 1. Purpose
Give owners and managers the core Phase 1 views: where each project stands on cost, what is on order or in stock, which reports are missing, labour usage, and the lead pipeline, exportable to Excel.

## 2. Boundary
- Owns: tables `rpt_*` (saved filters only), module `reports`.
- Provides: report endpoints and export files.
- Consumes: only exported query functions and published `<prefix>_v_*` views of other modules (listed in each module's `module.json`).
- Must not: read other modules' tables directly or store copies of their data.
- Cross-module additions (approved in CHANGES 2026-10-30, option 1): this spec's PR also adds the query interfaces listed in the Provides lines of P1-06, P1-11, P1-12 and P1-17, each with tests in the owning module and the owning `module.json` and `index.ts` updated. These are the only changes to those modules.
- Out of scope: profitability and financial reports (P2-08), accountant exports (P2-09), dashboards (Phase 7).

## 3. Data model
- `rpt_saved_filters(id, user_id, report_code, name, filter jsonb)`.
No other tables; every report is a query composition.

## 4. Business rules
- BR-1 **Project cost status:** per project and cost code: budget, committed, approved, posted, total used = committed + approved + posted, variance = budget - total used, percent used; totals per project; ordered by overspend.
- BR-2 **Stock:** on-hand quantity and value per store and item (company-owned valued by the valuation engine; client-owned shown by quantity with value blank), below-reorder list.
- BR-3 **Pending purchasing:** open requisitions, open PO lines with ordered, received and outstanding quantities, overdue by expected date.
- BR-4 **Labour:** worker-days and labour cost per project per month (approved attendance), headcount per day; for management and accountant roles only (rates).
- BR-5 **DPR compliance:** per project and date range, submitted vs missing report days.
- BR-6 **Lead pipeline:** counts and expected value per stage, conversion rate (won / (won + lost)) per period, overdue follow-ups.
- BR-7 **Client material reconciliation** per project (received, used, returned, balance).
- BR-8 Every report respects scope: supervisors see only assigned projects and no cost or rate data unless their role permits.
- BR-9 Every amount is computed by the owning modules; this module only filters, groups and sums with Decimal arithmetic.
- BR-10 Exports: XLSX and CSV with a header block (report name, filters, generated at in Asia/Karachi, generated by); export size limit 50,000 rows; large exports are refused with a message to narrow filters.
- BR-11 All lists paginate (default 50, max 200) and sort server-side; totals are computed over the whole filtered set, not the page.

## 5. API and UI
- `GET /reports/project-cost`, `/stock`, `/purchasing`, `/labour`, `/dpr-compliance`, `/pipeline`, `/client-material`; each accepts `format=json|csv|xlsx`.
- Screens: reports hub, filter bar with saved filters, tables with totals, export button.

## 6. Permissions
`reports.project-cost.read` (management, project_manager, accountant), `reports.stock.read` (storekeeper, procurement, management, accountant), `reports.purchasing.read` (procurement, management), `reports.labour.read` (management, accountant), `reports.dpr.read` (project_manager, management), `reports.pipeline.read` (management, project_manager).

## 7. Test requirements
- T-1 Each report against a scripted synthetic dataset created through the real module services; expected figures are hand-calculated in the test.
- T-2 Variance and percent used math including zero budget (percent null), overspend ordering.
- T-3 Scope: supervisor sees only assigned projects; rate-bearing reports denied.
- T-4 Totals computed over the whole set with pagination.
- T-5 Export format tests (headers, row counts, limit refusal).
- T-6 Property test: sum of per-cost-code totals equals the project total for random ledgers.
- T-7 Boundary test: the module's imports resolve only to other modules' `index.ts`.
- T-8 Route contract tests, component tests for tables; 100% coverage of service and policy.

## 8. Acceptance criteria
- AC-1 Each report matches the hand-calculated figures for the scenario dataset.
- AC-2 Exports open in Excel with correct numbers and header block.
- AC-3 A supervisor cannot see cost or wage data through any report route.
- AC-4 Definition of Done satisfied.
