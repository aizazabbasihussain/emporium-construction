# P2-09 Accountant exports and account tags

## 1. Purpose
Give the internal accountant everything needed to keep the official books outside the system: registers, ledgers and reports in fixed Excel/CSV layouts, with each transaction tagged with its chart-of-accounts code so a fuller ledger can be added later without re-entering history. This is not a general ledger.

## 2. Boundary
- Owns: tables `acc_*`, module `accounting-exports`.
- Provides: `tagTransaction(sourceRef)`, `listUntagged()`, `runExport(code, filters)`; export run log.
- Consumes: only exported query functions and published views of billing, receivables, payables, subcontracts, payroll, cash book, valuation, tax, projects.
- Must not: create journals, balances, trial balances or financial statements; must not modify source documents.
- Out of scope: general ledger, trial balance, balance sheet, cash-flow statement, period closing (constitution section 14; BACKLOG), direct integration with accounting software, bank feeds.

## 3. Data model
- `acc_accounts(code pk, name, type asset|liability|equity|income|expense, parent_code, active)` loaded from the accepted chart of accounts (P0-03); read-only in the UI except activation.
- `acc_mapping_rules(id, source_doc_type, condition jsonb, debit_account_code, credit_account_code, effective_from, active)` posting suggestions per document type (for example invoice issued: receivable and income accounts).
- `acc_tags(source_doc_type, source_doc_id, line_ref, account_code, tagged_by nullable, method rule|manual, tagged_at)`.
- `acc_export_runs(id, export_code, filters jsonb, row_count, checksum_sha256, file_id, run_by, run_at)`.

## 4. Business rules
- BR-1 Every financial document line (invoice lines, credit notes, bills, payments, receipts, cash transactions, payroll runs, stock issues and receipts value, expense claims) can carry account tags; the rule engine proposes tags from `acc_mapping_rules`; the accountant can accept or change them; tagged lines remain tagged when the rule later changes.
- BR-2 The "untagged" list shows documents without tags by type and date; exports include a column `account_code` (blank if untagged) and a warning count in the header block.
- BR-3 Exports available (fixed column layouts defined in `docs/exports/<code>.md`, versioned): sales register (invoices and credit notes by authority and month), purchase register (bills by authority and month), receipts register, payments register, cash and bank book per account, PDC register, customer and vendor ledgers, aging, withholding report (client-withheld and we-withheld by authority and month), payroll summary per month, stock valuation by store and category with method, project cost and profit summary, subcontractor statements.
- BR-4 Each export includes: header block (name, filters, period, generated at Asia/Karachi, generated by, schema version), data rows, and a footer with row count and control totals (sum of amounts) so the accountant can tie out.
- BR-5 Control totals are computed by the owning modules' own report functions and compared with the sum of exported rows; a mismatch aborts the export with an error.
- BR-6 Exports are generated as XLSX and CSV (UTF-8 with BOM for Excel), stored through the file store with a checksum, and logged in `acc_export_runs`; re-running with the same filters on unchanged data yields the same checksum for the data section.
- BR-7 Fiscal year (H-06, default July start) is used for period filters and labels only; no closing or locking is performed.
- BR-8 Permission is required for each export and all runs are audited.
- BR-9 Account tag backfill job: a command tags historical documents using current rules for untagged lines (dry run first, accountant confirms).
- BR-10 Layout changes require a new schema version; old versions stay reproducible for runs already made.

## 5. API and UI
- `GET /exports`; `POST /exports/:code/run` (filters) returns file link; `GET /exports/runs`; `GET /accounting/untagged`; `PUT /accounting/tags`; `POST /accounting/backfill/dry-run|commit`; `GET/PUT /accounting/mapping-rules`.
- Screens: exports hub with filters and history, untagged documents queue with bulk tagging, mapping rules editor.

## 6. Permissions
`accounting.export.run|read` (accountant, management), `accounting.tag.manage` (accountant), `accounting.rules.manage` (accountant).

## 7. Test requirements
- T-1 One test per export: scripted dataset, expected rows and control totals hand-verified, column layout matches the documented layout file (layout test reads `docs/exports/*.md`).
- T-2 Control-total mismatch aborts (inject a faulty provider).
- T-3 Rule-based tagging precedence, manual override persistence, rule changes do not retag.
- T-4 Untagged list and header warning count.
- T-5 Deterministic checksum for unchanged data.
- T-6 Fiscal year labeling with a July and a January start.
- T-7 Backfill dry run vs commit.
- T-8 Property test: sum of exported amounts equals the owning module's report total for random datasets.
- T-9 Route contract tests, repository integration tests, component tests; 100% coverage of domain, service and policy.

## 8. Acceptance criteria
- AC-1 Every export listed opens in Excel and ties out with its control totals on the scenario dataset.
- AC-2 Tags persist and can be bulk-assigned; untagged items are always visible.
- AC-3 No balance, trial balance or statement endpoint exists.
- AC-4 Definition of Done satisfied.

## 9. Open inputs
H-05 (chart of accounts: exports work with blank tags until answered), H-06 (default July allowed).
